WHAT YOU MUST DO MANUALLY (4 Steps, ~15 minutes)
───────────────────────────────────────────────────────────────────────────

STEP 1: CREATE SUPABASE PROJECT (5 min)
  1. Go to https://app.supabase.com
  2. Click "New Project"
  3. Name: goal-day-website
  4. Generate password
  5. Choose region
  6. Wait 2-3 minutes
  7. Go to Settings → API
  8. Copy "Project URL"
     Example: https://xyzabc123def.supabase.co
  9. SAVE THIS → becomes SUPABASE_URL for Vercel

STEP 2: CREATE DATABASE TABLE (2 min)
  1. In Supabase dashboard, click "SQL Editor"
  2. Click "New Query"
  3. Copy entire content of: supabase/schema.sql
  4. Paste into editor
  5. Click "Run"
  6. Expect: "Query executed successfully"

STEP 3: INSERT YOUR DATASET (3 min)
  1. SQL Editor → "New Query"
  2. Open file: C:\Users\ymehm\secrets\data.json
  3. Select ALL content (Ctrl+A)
  4. Copy (Ctrl+C)
  5. Paste this SQL into editor:
     
     INSERT INTO golday_data (id, data) VALUES (
       1,
       '[PASTE_YOUR_JSON_HERE]'::jsonb
     )
     ON CONFLICT (id) DO UPDATE 
       SET data = EXCLUDED.data,
           updated_at = NOW();
  
  6. Replace [PASTE_YOUR_JSON_HERE] with your JSON
  7. Click "Run"
  8. Expect: "Insert 1 row"

STEP 4: CONFIGURE VERCEL (5 min)
  1. Go to Vercel Project → Settings → Environment Variables
  2. Click "Add Environment Variable"
  3. Add first variable:
     Name: SUPABASE_URL
     Value: [Your Project URL from STEP 1]
     Environments: Production, Preview
     Sensitive: NO
     Click "Add"
  
  4. Click "Add Environment Variable" again
  5. Add second variable:
     Name: SUPABASE_SERVICE_KEY
     Value: [Copy from Supabase Settings → API → service_role (secret)]
     Environments: Production, Preview
     Sensitive: YES (IMPORTANT - check this box!)
     Click "Add"
  
  6. Done

TROUBLESHOOTING
───────────────────────────────────────────────────────────────────────────

"Table does not exist" error
  → Re-run supabase/schema.sql in Supabase SQL Editor

"HTTP 401" in Vercel logs
  → Verify SUPABASE_SERVICE_KEY is correct and marked as Sensitive in Vercel

"Invalid JSON" error when inserting data
  → Make sure you copied the ENTIRE contents of secrets/data.json

Frontend shows "No data source available"
  → Check Vercel logs
  → Verify data was inserted: SELECT * FROM golday_data; in Supabase

Need to rollback?
  → git revert HEAD
  → git push origin master
  → Falls back to local secrets/data.json


ARCHITECTURE SUMMARY
───────────────────────────────────────────────────────────────────────────

Production Flow:
  Browser → Vercel Edge → Node.js (api/data.js)
          → HTTPS to Supabase
          → PostgreSQL (golday_data table)
          → Extract public fields
          → Return JSON to frontend

Development Fallback:
  If Supabase env vars missing:
  → Reads from secrets/data.json (local)
  OR from data/public.json (if exists)

Data Flow:
  secrets/data.json → [once] → Supabase Database
                    ↓
  Supabase Database ←→ [per request] ← Frontend API calls
                    ↓
  /api/data endpoint ←→ Browser
                    ↓
  golgunu.html displays stats
